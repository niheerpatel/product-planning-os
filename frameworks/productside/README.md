# Productside Framework — Lifecycle Reference

**Source**: Productside (formerly 280 Group)
**Core idea**: An outcome-driven product lifecycle where outcomes > outputs, with continuous feedback loops.

## Lifecycle Phases

```
Context → Discover + Investigate → Discover + Define → Create → Deliver → Iterate
   ↑                                                                        |
   └────────────────────────── Feedback Loop ───────────────────────────────┘
```

### 1. Context
**Purpose**: Understand the landscape before discovery.
- Market dynamics, size, growth
- Customer segments and their characteristics
- Competitor positioning and strategies
- Internal constraints (technical, organizational, financial)
- Role clarity: who owns what decisions

**Key question**: Can you articulate the market, the customer, and the constraints without guessing?

### 2. Discover + Investigate
**Purpose**: Find real problems worth solving.
- Customer interviews and observation
- Quantitative data analysis
- Market research
- Hypothesis formation (not conclusion-jumping)

**Key question**: Do you have evidence (not just opinions) for the top problems?

### 3. Discover + Define
**Purpose**: Bet on the right problem + solution.
- Problem statement crystallization
- Solution scoping — find the smallest valuable outcome
- Stakeholder alignment on the bet
- Success criteria definition

**Key question**: Is this the smallest thing that would prove value?

### 4. Create
**Purpose**: Build to learn, not to ship.
- Prototype or MVP development
- Usability testing
- Technical validation
- Learning-focused iteration

**Key question**: Did you learn what you needed? Does data support scaling?

### 5. Deliver
**Purpose**: Ship, measure, learn.
- Launch execution
- Instrumentation and measurement
- Leading indicator → lagging KPI connections
- Customer feedback collection

**Key question**: Are leading indicators trending in the right direction?

### 6. Iterate
**Purpose**: Close the loop.
- Delivery data → new hypotheses
- Strategy update based on learnings
- Next discovery cycle informed by real-world results
- Retire what doesn't work

**Key question**: Has the strategy been updated based on what you learned?

## Key Principle: Outcomes > Outputs

| Outputs (avoid) | Outcomes (prefer) |
|-----------------|-------------------|
| "Ship feature X" | "Reduce customer churn by 15%" |
| "Build dashboard" | "Enable data-driven decisions for ops team" |
| "Launch mobile app" | "Increase field technician efficiency by 20%" |
| "Complete 12 stories" | "Validate that customers will pay for self-service" |
